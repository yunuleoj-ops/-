# 마법진 획별 복소 푸리에 분해 — 확정 설계안

**작성일** 2026-08-13 · **상태** 사용자 승인 완료, 구현 계획 대기

사용자가 그린 마법진을 정확한 수학식으로 표현한다. 기존 `r(θ)` 극좌표 근사는 각도마다 반지름이 하나뿐인 단일값 함수여서, 한 방향에 여러 곡선이 겹치는 마법진을 원리적으로 표현할 수 없었다(정확도 81~90%에서 정체). 이를 획별 복소 푸리에 분해로 대체한다.

작성 근거: 5개 렌즈(math/perf/ui/integration/edge) 분석 81건 + 2건의 비판. 비판 1이 무효화한 perf 벤치마크 수치는 채택하지 않고 독립 재측정한 값으로 대체했다.

## 1. 수학적 정식화

### 1.1 좌표계

캔버스 점 `p = x + iy` (viewBox 0..100, y 아래로 증가), 중심 `c = 50 + 50i`.

```
z = conj(p − c) = (x − 50) + i(50 − y)
역변환: x = 50 + Re z,  y = 50 − Im z
```

분석 파이프라인 진입 시 **단 한 번** 적용한다. 이후 모든 계수·연산자·수식은 원점 중심 수학 좌표에서만 정의된다.

이 형태를 고르는 이유는 "중심 이동 + y 뒤집기"가 정확히 "평행이동 후 켤레"라는 한 줄 항등식이기 때문이다. 그 결과:
- 어떤 대칭 연산자에도 평행이동 항이 등장하지 않는다.
- 화면상의 좌우/상하 반사가 수학 좌표에서 순수 켤레 연산으로 떨어진다.
- 획의 위치 오프셋이 특수 케이스가 아니라 `c₀`(닫힘) 또는 `z₀`(열림) 단일 계수가 된다.

부호 주의: 켤레를 취하므로 수학 좌표에서의 회전 방향이 화면과 반대다. 다만 순환군 궤도 `{ω^k z}`는 `ω = e^{2πi/m}`이든 `e^{−2πi/m}`이든 **집합으로서 동일**하므로 렌더 결과는 현재 `transformPoint`와 완전히 같다. 교과서 부호를 쓰되 복사본 인덱스 `k`의 의미만 바뀐다는 주석을 남긴다.

비판 D-7 반영: perf가 `c₀`를 캔버스 중심과 DFT 직류항 두 가지로 쓴 표기 충돌은 이 좌표 정의로 항목 자체가 소멸한다.

### 1.2 획 분류 — 세 갈래, 커밋 시 1회 판정 후 동결

```
L = 재샘플 전 호길이,  g = |z(1) − z(0)|

퇴화(point):  L < 1.0
닫힘(closed): L > 18  ∧  g ≤ min(8, max(1.5, 0.03·L))
열림(open):   그 외
```

**분석용 임계는 게임용 임계의 진부분집합이다.** 게임 지표(`metrics.closed → intersections → complexity → power → grade`)가 쓰는 현행 판정 `L > 18 ∧ g < 8`은 **단 한 글자도 바꾸지 않는다.** 분석용 임계에 `min(8, …)`을 씌운 것이 이 포함관계를 보장한다. 이로써 같은 그림의 MAGIC POWER와 등급이 이번 변경으로 절대 움직이지 않는다(비판 C-3 반영).

임계 계수를 0.03으로 잡은 근거는 재측정된 **오분류 비용의 비대칭성**이다. 이 값은 어느 렌즈도 측정하지 않았다.

| 원호 각도 | g/L | 열림 분기(현분리) | 닫힘 분기(현 추가) |
|---|---|---|---|
| 360° | 0.000 | 5항 | **1항** |
| 350° | 0.029 | 5항 | **1항** |
| 340° | 0.059 | 6항 | 1항 |
| 320° | 0.122 | **6항** | 4항 |
| 300° | 0.191 | **6항** | 10항 |
| 180° | 0.637 | **3항** | 16항 |

읽는 법:
- 닫힌 획을 열림으로 오판 → 1항이 5항이 된다. 비용 4항, 화면은 정상.
- 열린 획을 닫힘으로 오판 → 3항이 16항이 되고, **사용자가 그리지 않은 현이 화면에 나타난다.** 정확도 지표의 진리값이 무너진다.

따라서 임계는 반드시 "열림 쪽으로 보수적"이어야 하고, 그렇게 잡았을 때의 최대 손실은 4항으로 T_max=24 대비 무해하다. 즉 이 임계는 원래 예상과 달리 깨지기 쉬운 결정이 아니다.

파생 결정: **닫힘으로 판정된 획은 렌더에서도 실제로 닫는다**(path에 `Z` 추가). 정확도의 진리값이 "화면에 그려진 곡선"이므로 화면과 분석이 갈라지면 지표가 무의미해진다. g ≤ 0.03·L이므로 시각적 변화는 무시할 수준이고, 마법진은 오히려 정돈되어 보인다.

### 1.3 호길이 균등 재매개화

절차:

1. **밀집화**: 렌더와 동일한 Catmull-Rom 곡선을 세그먼트별 `clamp(ceil(현길이 / 0.25), 4, 64)` 스텝으로 평가 → 밀집 폴리라인 D (간격 ≈ 0.25단위). `|D| ≤ 4096`으로 상한, 걸리면 간격을 `L/4096`으로 재계산해 균등성만 유지.
2. **누적 현길이 표** `s_j`, 총길이 `L = s_last`.
3. **two-pointer 전진 순회** O(|D| + P). 목표 호길이 `u_k`가 단조 증가하므로 이진탐색 불필요. 구간 내 선형보간.
4. 닫힘: `u_k = kL/P`, k = 0..P−1 (끝점 중복 없음). 열림: k = 0..P (양 끝 포함).

이것이 왜 협상 불가능한 전제인가: 푸리에 계수의 감쇠와 에너지 분포는 매개변수화에 의존한다. `|z'(t)|`가 변하면 그 자체가 주파수 변조로 작동해 형상과 무관한 고주파 에너지를 만든다. 현재 `curvePoints`는 세그먼트당 무조건 8등분인데, RDP(허용 0.35)가 직선 구간의 점을 걷어내고 곡률 구간에 점을 남기므로 세그먼트 길이가 20배 이상 차이 난다. 지금의 매개변수 속도는 최악에 가깝다.

호길이 균등이 주는 것:
- L² 오차가 곧 기하학적 거리 오차 → 정확도 지표가 눈으로 검증 가능해진다.
- 그리는 속도·제어점 배치에 무관한 계수.
- `|z'| = L` 상수 → 파스발 항등식 `Σ(2πn)²|c_n|² = L²`이 성립해 자체 검증 수단이 생긴다. 재측정 결과 원 1.0000, 육각형 0.9986, 별 0.9929로 성립을 확인했다.

선형보간 오차는 간격 h=0.25에서 새그 `h²κ/8` 기준 0.008단위 이하로, 절대 오차 하한 0.15단위보다 한 자릿수 작다.

**정정(비판 C-7)**: math 렌즈의 "같은 모양이면 같은 식"이라는 주장은 그대로는 거짓이다. 호길이 균등화는 **속도 의존성만** 제거하고 시작점·방향 의존성은 남긴다. 정확한 진술은 "같은 모양을 같은 지점에서 같은 방향으로 그리면 같은 식"이다. 정준화를 v1에서 채택하지 않으므로(§8-Q3) 이 문구를 UI와 문서 어디에도 쓰지 않는다.

### 1.4 표본 수와 후보 대역

```
P = clamp(round(2L), 128, 512), 짝수 보정   → 표본 간격 L/P ≤ 0.5단위
K_max = min(floor(P/4), 64)
T_max = 24 (유지 항 상한)
```

`K_max ≤ P/4`인 이유는 나이퀴스트가 아니라 **지표의 유의미성**이다. `K = P/2`에서는 DFT가 표본을 정확히 보간해 오차가 0이 되고 정확도가 자기충족적이 된다. 최소 2배 오버샘플 여유를 강제한다. integration의 "하드 상한 N/2 = 128, 나이퀴스트"는 이 지점에서 잘못된 경계다(비판 C-9).

`P = 2L`의 근거: RDP 허용치 0.35 때문에 그림에 실재하는 최소 특징 크기가 약 1~2단위다. 파장 2단위를 해상하려면 간격 ≤1단위, 안전계수 2를 붙여 0.5단위.

`T_max = 24`의 근거는 연산량이 아니라 가독성이다. 실측 항 수:

| 도형 | 항 |
|---|---|
| 직선(열림) | **0** |
| 원 | **1** |
| 반원(열림) | 3 |
| 완만한 호(열림) | 3 |
| 물결(열림) | 5 |
| 정육각형 | 4 |
| 손떨림 원(고주파 노이즈 포함) | 4 |
| 정사각형 | 6 |
| 오각별 | 8 |

최악이 8항. perf의 64, integration의 48은 무효 픽스처에서 나온 과대값이고, edge의 전역 예산 400은 해결할 문제가 없다.

### 1.5 두 개의 변환

**닫힌 획** — 표본 `z_k`, k = 0..P−1:

```
c_n = (1/P) Σ_k z_k e^(−2πi n k/P),   n ∈ [−P/2, P/2)
z(t) = Σ_{n∈A} c_n e^(2πi n t)
```

**열린 획** — 표본 `z_k`, k = 0..P:

```
z₀ = z_0,  Δ = z_P − z_0,  r_k = z_k − z₀ − (k/P)Δ    (r_0 = r_P = 0)
b_n = (2/P) Σ_{k=1}^{P−1} r_k sin(πnk/P),   n = 1..P−1     [DST-I]
z(t) = z₀ + Δ·t + Σ_{n∈A} b_n sin(πn t)
```

**왜 현 분리인가.** 세 방식의 계수 감쇠 차수가 다르다.

- 단순 반복: `z(1) ≠ z(0)` → 값 불연속 → `|c_n| = O(1/n)`. 깁스 오버슛이 획 끝에 갈고리로 남는다.
- 왕복(짝) 확장: 값은 연속이나 반환점에서 속도 역전 → 도함수 점프 → `O(1/n²)`.
- 현 분리 + 홀수 확장: `r`이 양 끝에서 홀함수 → `r'`이 우함수 → 도함수 연속, `r''`만 점프 → `O(1/n³)`.

**정정(비판 D-1)**: math 렌즈는 왕복 확장을 "주기가 곡선을 두 번 덮으므로 조화 지수가 2배"라는 이유로 기각했는데, 이 논거는 자기 안도 함께 친다 — 현 분리의 홀수 확장도 주기 2다. 옳은 이유는 주기가 아니라 **감쇠 차수**다. 논거를 정정해 두지 않으면 다음 리뷰에서 재론된다.

부가 이점:
- **직선 획은 r ≡ 0이므로 0항으로 정확하다.** 마법진의 방사 직선·별 모양 변이 공짜가 된다. 거울 확장은 같은 직선에 14항을 쓴다.
- `r(0) = r(1) = 0`이 항 개수와 무관하게 유지되므로 재구성 곡선의 끝점이 절대 어긋나지 않는다.
- 사인은 실수 기저라 대칭 연산자가 인덱스 뒤집힘 없이 계수에 그대로 작용한다.
- 사용자 설명 부채 0. 거울 확장은 "t는 정방향 후 역방향 1회 왕복"이라는 각주와, 켤레쌍 때문에 항 수가 명목상 2배로 보이는 문제를 낳는다.

**승인된 표기와의 관계.** 승인된 형태는 `z(t) = Σ c_n e^(2πint)`였다. 닫힌 획은 이 형태 그대로다. 열린 획은 그 앞에 아핀 항이 붙는다. 모달에는 `sin(πnt) = (e^{iπnt} − e^{−iπnt}) / 2i`를 병기해 같은 복소 푸리에임을 밝힌다. 설명 문장은 "닫힌 획 = 원형, 열린 획 = 원형 + 직선 성분".

**구현 메모.** FFT를 쓰지 않는다. `cosTable[j] = cos(2πj/P)`, `sinTable[j] = sin(2πj/P)`를 획마다 한 번 만들고 `(n·k) mod P` 인덱스로 조회해 루프 안의 삼각함수 호출을 0으로 만든다. P ≤ 512, n ≤ 64면 정수 곱이 2^53을 넘지 않는다. 후보 대역 `|n| ≤ K_max`까지만 계산한다.

DST-I는 라딕스-2 복소 FFT로 바로 돌지 않으므로 perf의 FFT 권고는 애초에 이 변환과 호환되지 않는다. 그리고 perf 자신이 측정한 렌더 경로 3.66ms가 푸리에 전체보다 4배 비싼 병목이므로, FFT는 잘못된 곳을 최적화한다.

### 1.6 항 선택과 정지 조건

대역 `|n| ≤ K_max` 안에서 진폭 내림차순으로 항을 하나씩 추가하며 파스발 꼬리 에너지를 갱신한다. **재적합 루프를 만들지 않는다** — 계수 `c_n`은 항 개수와 무관하게 정해지므로 재계산할 이유가 없다.

직교 기저에서 L² 오차를 최소화하는 최적 T항 근사가 "진폭 상위 T개"라는 것은 정리로 보장된다. 대역 잘라내기(`|n| ≤ K`)는 마법진 스펙트럼의 희소성(m겹 대칭이면 `n ≡ 1 mod m`만 생존)을 낭비한다.

**꼬리 에너지:**

```
닫힘: S² = Σ_{n≠0}|c_n|² = (1/P)Σ_k|z_k|² − |c₀|²
      e_A² = S² − Σ_{n∈A}|c_n|²

열림: e_A² = (P / (2(P+1))) · (Σ_{n=1}^{P−1}|b_n|² − Σ_{n∈A}|b_n|²)
```

DST-I 직교성 `Σ_{k=1}^{P−1} sin(πnk/P)sin(πmk/P) = (P/2)δ_{nm}`이 정확히 성립하므로 열린 획도 닫힌 획과 동일하게 정확한 에너지 회계가 가능하다.

**정규화 분모 — 앱 전체에 하나만 존재한다(비판 D-4):**

```
S = 표본의 중심 대비 RMS 거리 = sqrt( mean_k |z_k − mean(z)|² )
정확도 = clamp(1 − e_A / S, 0, 1)
```

기각한 후보와 이유:
- **bbox 대각선(edge)**: 회전 불변이 아니다. 45° 돌린 같은 획이 다른 정확도를 낸다. 회전 연산자 테스트와 직접 충돌한다.
- **획 길이(ui)**: 좁은 영역의 긴 낙서일수록 유리해진다(L은 크고 오차는 국소적). 틀린 분모를 화면에 명시하면 그 오류가 하중을 받는다.
- **잔차 형상 에너지(integration)**: 완전한 직선에서 0/0 → NaN.
- **원점 거리 평균**: 중심을 지나는 획에서 0에 수렴해 정확도 폭발.

**정지 조건** (셋 중 하나):

```
(1) e_A ≤ (1 − τ)·S,  τ = 0.99
(2) e_A ≤ 0.15 캔버스 단위          ← 절대 하한, 작은 획의 항 낭비 방지
(3) |A| = T_max = 24
```

`c₀`(닫힘), `z₀`와 `Δ`(열림)는 무조건 포함하고 항 수에 세지 않는다. **최소 항 하한을 두지 않는다** — 직선이 0항이어야 하기 때문이다(비판 C-2: edge 렌즈 내부의 `[1] 하한 금지` vs `[6-c] 최소 4항 보장` 자기모순은 전자를 채택해 해소).

**정정(비판 D-5)**: 0.15라는 상수가 math("오차 ≤ 0.15에서 종료")와 edge("다음 항 진폭 < 0.15에서 종료")에서 서로 다른 규칙에 같은 값으로 쓰였다. 두 규칙은 합성하면 비일관적이다(진폭 0.14짜리 항이 오차를 0.30→0.16으로 줄이는 데 필요할 수 있다). **오차 기준 하나만 채택하고 진폭 바닥 규칙은 기각한다.** 노이즈 추적 방지라는 edge의 목적은 이미 재샘플의 저역통과 효과와 오차 하한이 함께 달성한다 — 손떨림 원이 4항으로 끝난다는 실측이 그 증거다.

최종 A가 정해진 뒤 **한 번만** 재구성해 최대 오차 `max_k |z_k − ẑ_k|`를 진단용으로 계산한다. 이것이 `3·e_A`를 넘으면 항을 1.5배로 한 번 더 늘린다(국소 꺾임 보호). 표시는 RMS 정확도가 주 지표, 최대 오차가 부 지표.

**전역 항 예산은 폐기한다(비판 C-1).** edge의 `Σ N ≤ 400`은 (a) 실측 최악이 획당 8항이라 불필요하고, (b) 13번째 획 추가가 1~12번 획의 항 수를 바꾸므로 획 객체 키 캐시와 원리적으로 양립 불가하며, (c) "같은 그림인데 그리는 순서에 따라 식이 달라진다"는 재현 불가능성을 낳는다. 획별 상한 T_max=24만 남긴다.

### 1.7 대칭 연산자

원점 중심 수학 좌표에서:

```
회전 C_m:       R z = ω z,  ω = e^(2πi/m),  복사본 k: R^k z = ω^k z,  k = 0..m−1
반사(축 각 φ):  M_φ z = e^(2iφ) z̄
  · mirrorX (화면 x→100−x, 세로축 반사): M z = −z̄
  · mirrorY (화면 y→100−y, 가로축 반사): M z = z̄
```

계수에 대한 작용:

```
닫힘: 회전 c_n ↦ ω^k c_n      /  반사 c_n ↦ e^(2iφ) · conj(c_{−n})
열림: 회전 (z₀,Δ,b_n) ↦ ω^k·(z₀,Δ,b_n)
      반사 (z₀,Δ,b_n) ↦ e^(2iφ)·(conj z₀, conj Δ, conj b_n)
```

반사에서 **인덱스가 −n으로 뒤집히는 것은 지수 기저(닫힘)에서만** 발생한다. 열린 획의 사인 기저는 실수 기저라 인덱스 뒤집힘이 없다 — 현 분리를 택하는 또 하나의 실질적 이득이다.

**검증 완료.** 재측정에서 좌우 반사에 대해 옳은 규칙 `−conj(c_{−n})`의 최대 오차는 8.55e-15, 틀린 규칙 `−conj(c_n)`은 3.0e+1이었다. 근사가 아니라 정확한 항등식이다.

**edge의 테스트 지침 정정(비판 C-5).** edge는 "원, 직선에서는 틀려도 같아 보인다"고 했는데 원은 정반대다 — `c_1 = R`, `c_{−1} = 0`이므로 원이 이 버그를 즉시 드러낸다(재측정: 오차 30.0). 실제로 버그가 숨는 경우는 켤레 대칭을 갖는 계수, 즉 거울 확장된 열린 획이다(그 경우 `c_n = c_{−n}`이라 두 규칙이 항상 같은 값을 낸다). 현 분리를 택하면 이 은폐 경로 자체가 사라진다. 테스트는 **원과 비대칭 닫힌 획 둘 다**로 한다.

**나이퀴스트 빈 예외(신규 발견).** 닫힘 인덱스 범위 `[−P/2, P/2)`에서 `n = −P/2`는 반사 시 `+P/2`로 사상되는데 그 인덱스가 범위 밖이다(`c_{−P/2} ≡ c_{P/2}` 별칭). 재측정에서 비대칭 획의 옳은 규칙 오차가 4.14e-3으로 머신 엡실론이 아니었던 원인이 이것이다. 실무적으로는 `K_max ≤ P/4` 규칙 때문에 이 빈이 절대 채택되지 않아 무해하지만, **전 대역 자체 검증 테스트에서는 반드시 걸린다.** 반사 규칙 구현에 `n = −P/2` 특수 케이스를 명시하거나, 후보 대역을 대칭 구간 `|n| ≤ K_max`로 제한해 원천 차단한다. 후자를 채택한다.

### 1.8 전체 도형 표기

```
Z(t) = ⋃_j ⋃_{k=0}^{m_j − 1} S_j^k [ z_j(t) ],   t ∈ [0,1]
```

**기호 통일(비판 D-6)**: 전체 도형 기호는 `Z`, 결합 기호는 `⋃`. edge의 `Σ`는 곡선을 더하라는 뜻이 되어 틀렸다(궤도의 합집합이다). ui의 `Γ`, `⊕`도 `Z`, `⋃`로 통일한다. 헤드라인 문자열에 그대로 들어가는 기호이므로 새어 나가면 안 된다.

**대칭은 획별로 표기한다(edge [7-a] 채택).** `Stroke`가 자기 `symmetry`/`rotationCount`를 들고 있어 한 도형에 회전 6회 획과 자유 획이 공존하는 것이 정상 사용 경로다. 모든 획이 **동일한 (symmetry, rotationCount)** 쌍일 때만 `⋃_{k=0..5} R^k`처럼 구체 범위를 쓰고, 하나라도 다르면 `⋃_j S_j`로 낮춘다. 표기 강등은 정보 손실이 아니라 거짓 회피다.

### 1.9 자체 검증 항등식

개발 중 assert할 불변식:

1. **호길이 파스발**: `Σ_n (2πn)²|c_n|² = L²` (전 대역). 재매개화 버그·좌표 부호 실수·정규화 상수 실수를 한 줄로 잡는다. 재측정 성립 확인(오차 0.7% 이내, 다각형의 코너 이산화 때문).
2. **전 대역 재구성 일치**: A = 전 후보일 때 `e_A → 0`.
3. **대칭 연산자 항등식**: `fit(R z) == R·fit(z)` (계수 비교, 1e-12).

`lib/*` 어느 파일에도 `"use client"`를 붙이지 않고 React 타입을 import하지 않는다. 특히 `eventPoint`는 React의 `PointerEvent<SVGSVGElement>`를 받으므로 DOM 전역 `PointerEvent`와 이름이 충돌한다 — 좌표 변환처럼 보여도 컴포넌트에 남긴다.

### lib/fourier.ts — geometry, resample만 import

```
type Complex = { re: number; im: number }
type Term = { n: number; re: number; im: number }

type Spectrum =
  | { kind: "point";  length: number }
  | { kind: "closed"; c0: Complex;              terms: Term[]; stats: FitStats }
  | { kind: "open";   z0: Complex; delta: Complex; terms: Term[]; stats: FitStats }

type FitStats = {
  P: number            // 표본 수
  arcLength: number
  normS: number        // 정확도 분모
  rmsError: number
  maxError: number
  accuracy: number
  capped: boolean      // T_max 도달로 종료
}

type FitOptions = { target?: number; maxTerms?: number; absFloor?: number }

fitStroke(points: Point[], closure: Closure, options?: FitOptions): Spectrum
truncate(spectrum: Spectrum, termCount: number): Spectrum    // 슬라이더용, 재변환 없음
reconstruct(spectrum: Spectrum, q: number): Point[]          // 오버레이용
applyOperator(spectrum: Spectrum, symmetry: Symmetry, count: number, copy: number): Spectrum
```

**타입 설계는 비판 C-6을 반영해 integration 안을 재작성했다.** integration의 `StrokeSpectrum`에는 (a) 아핀 항 `Δ`를 담을 자리가 없었고(`center` 하나로는 표현 불가), (b) 퇴화 획 상태를 담을 필드가 없었으며(`truncated`와는 다른 개념), (c) `strokeId`가 들어 있어 integration 자신이 경고한 id↔기하 결합을 재생산했다. 판별 유니온으로 (a)(b)를 해결하고 `strokeId`를 제거했다.

`truncate`가 별도로 있는 이유: 항 수 슬라이더가 재변환 없이 항 부분집합만 갈아끼우기 위함이다.

### lib/polar.ts — 기존 r(θ) 이관, 코드 변경 없음

```
radialProfile(strokes: Stroke[]): number[] | null
polarFormula(strokes: Stroke[]): { formula: string; accuracy: number }
```

**강등하되 삭제하지 않는다.** 획별 푸리에는 획을 아무리 정확히 표현해도 "이 마법진이 육각형에 가깝다"는 전역 진술을 못 한다. r(θ)는 이 앱에서 유일하게 도형 전체를 하나의 값으로 서술하는 기술자이고, 50줄이며 이미 동작한다.

단 **`polarFormula.accuracy`는 UI 어디에도 노출하지 않는다.** 앱 전체에서 정확도 숫자는 푸리에 것 하나만 존재한다. 푸터가 87%, 모달이 99%면 사용자는 어느 쪽이 거짓말인지 묻게 되고, 정답인 "둘 다 다른 것을 재고 있다"를 UI로 설명할 방법이 없다. r(θ)를 "외곽 실루엣 근사"로 재정의하면 그 81~90%는 결함이 아니라 그 표현의 정의역이 된다.

**인과 정정(비판 B-3)**: math와 perf가 모두 현재의 81~90% 정체를 "열린 획 깁스"에 귀속시켰는데, 현재 코드에는 획별 푸리에가 없다. 실제 원인은 `page.tsx`의 `MAX_TERMS = 4` 하드 상한과 상위 4항 절단, 그리고 r(θ)가 단일값 함수라는 원리적 한계다. 이 오귀속을 설계 문서에 남기면 나중에 "깁스를 고쳤는데 왜 안 오르나"라는 잘못된 디버깅을 부른다.

### lib/analysis.ts — 오케스트레이터

```
type StrokeAnalysis = { stroke: Stroke; spectrum: Spectrum; operator: OperatorDesc }
type CircleAnalysis = {
  metrics: Metrics
  strokes: StrokeAnalysis[]
  totalTerms: number
  accuracy: number            // 호길이 가중 평균
  worst: { index: number; accuracy: number } | null
  uniformSymmetry: { symmetry: Symmetry; count: number } | null
  silhouette: string          // polarFormula의 문자열만
}
analyze(strokes: Stroke[], options?: FitOptions): CircleAnalysis
```

**전체 정확도 = 호길이 가중 평균.** 대칭 복사본 수를 가중치에 곱하지 **않는다** — ui가 수학팀에 넘긴 질문(비판 C-8)의 답이다. 대칭 복사는 등거리변환이라 추가 오차가 정확히 0이므로 오차 집계에 8배 기여할 근거가 없다. 호길이 가중은 퇴화 획의 가중치를 자동으로 0으로 만드는 부수 효과도 있다.

가중 평균은 나쁜 획 하나를 숨길 수 있으므로 `worst`를 항상 함께 계산해 모달에 병기한다. 획이 1개면 `worst = null`(중복 표기 생략).

### lib/formatting.ts — 타입만 보고 수치 계산을 하지 않는다

```
formatOperator(symmetry: Symmetry, count: number): string          // "R₆", "M_x", "I"
formatSummarySentence(a: CircleAnalysis): string                    // 푸터 앞부분
formatStructure(a: CircleAnalysis): string                          // "Z(t) = ⋃ R^k z_j(t)"
formatStrokeExpr(s: StrokeAnalysis, index: number): string          // 모달 한 줄
formatLatex(a: CircleAnalysis): string                              // 복사 전용
```

formatting을 fourier에서 떼는 이유: 같은 `Spectrum`을 푸터/모달/클립보드 세 가지로 렌더해야 하는데, 문자열 조립이 수학 모듈 안에 있으면 표기를 바꿀 때마다 수학 파일을 건드리게 되고 테스트가 문자열에 결합된다. LaTeX 생성기는 유니코드 생성기와 별개 함수로 두어 이스케이프가 섞이지 않게 한다.

### lib/storage.ts

```
const DRAFT_KEY = "arcana-draft-v1"     // 키를 올리지 않는다
loadDraft(): Stroke[]
saveDraft(strokes: Stroke[]): void
saveCard(payload: CardPayload): void
```

키는 그대로 두고 페이로드만 `{ version: 2, strokes }` 봉투로 감싼다. 로더는 `Array.isArray(parsed)`로 v1/v2를 구분한다 — 배열 대 객체는 공짜로 얻는 완벽한 판별자다. 키를 v2로 올리면 기존 사용자의 그림이 전부 사라지는데, 그리기 앱에서 그건 마이그레이션이 아니라 데이터 손실이다.

**계수는 저장하지 않는다.** 냉시작 전체 재계산이 1ms 수준인 반면, 계수를 직렬화하면 페이로드가 3~4배가 되고 그 직렬화가 커밋 직후 동기로 돈다. 저장으로 아끼는 것보다 저장 자체가 비싸다.

## 3. 데이터 흐름

```
pointerdown
  └ startStroke: id 생성(crypto.randomUUID, 폴백 있음) → active 상태
     ※ id는 이벤트 핸들러와 effect에서만 생성. 렌더 중 생성하면 hydration mismatch

pointermove
  └ active.points 추가 → StrokeLayer(active)만 재렌더
     ※ 분석 없음. 값싼 지표(길이·점 수)만 갱신 가능

pointerup / endStroke
  └ simplify(points, 0.35)
  └ classifyClosure(points) → closure 동결
  └ 총 호길이 < 1.0 이면 커밋하지 않고 폐기
  └ setStrokes([...strokes, stroke])

useMemo 1단  [strokes]
  └ strokes.map(s => weakMapCache.get(s) ?? fitStroke(...))
     · densify → resampleUniform → toComplex
     · closed: 테이블 DFT      / open: 현 분리 + DST-I
     · 진폭 정렬 → 파스발 그리디 → 정지 조건 → 진단 재구성 1회
     · WeakMap<Stroke, Spectrum>에 저장
     ※ 실비용 = 변경된 획 수에 비례 (신규 획 1개면 1회 적합)

useMemo 2단  [spectra, target]
  └ analyze(): 연산자 부여, 가중 평균, worst, totalTerms, 문자열
     ※ 목표 정확도를 바꿔도 1단은 다시 돌지 않는다

렌더
  ├ 푸터: formatSummarySentence + formatStructure
  ├ 카드 뒷면: 구조식 + 분해 한 줄
  └ FormulaSheet (열렸을 때만)
      ├ 오버레이: reconstruct(truncate(spectrum, sliderN), Q) → 원본 위 겹쳐 그림
      ├ 획 카드: formatStrokeExpr
      └ 계수표: details 접힘

localStorage
  └ [strokes] → saveDraft (계수 제외)
```

**활성 획은 절대 분석하지 않는다.** 성능 때문이 아니라 데이터 안정성 때문이다: (1) active는 `simplify` 이전이라 손떨림 원본 점이 그대로 남아 확정 획과 다른 전처리를 거친다 — 커밋 순간 식이 튄다. (2) 미완성 곡선의 계수는 획이 자랄 때마다 크게 요동쳐 초당 60~120회 바뀌는 숫자는 읽을 수 없다. (3) 닫힘/열림 판정이 그리는 도중 계속 뒤집혀 분기가 프레임마다 달라진다.

**렌더는 제어점 변환, 분석은 재샘플 후 변환.** 지금은 대칭이 아핀이라 두 순서가 같아 문제가 없다. 비아핀 대칭(나선, 스케일 그라디언트)을 추가하면 화면과 식이 조용히 갈라진다. 이 교환법칙을 테스트로 못 박는다(§7-T2).

## 4. UI

### 4.1 설계 원칙 두 개

**(a) 이 기능의 신뢰는 계수표가 아니라 오버레이가 만든다.** 사용자는 `ρ∠φ` 행을 하나도 검산할 수 없고, 그 값을 보고 다음에 무엇을 다르게 그릴지도 알 수 없다. 검증도 행동도 불가능한 숫자는 신뢰를 올리지 않고, 일정 분량을 넘으면 과시로 읽혀 오히려 깎는다. "이 식이 내 그림이다"를 1초에 납득시키는 유일한 방법은 식이 자기 그림 위에 겹쳐 그려지는 것을 보는 것이다. math 렌즈가 이것을 "개발용 디버거, 기본 꺼짐"으로 격하한 것은 우선순위 오류이므로 뒤집는다.

**(b) 변하는 값이 앞에 온다.** 새 설계에서 정확도는 목표까지 항을 늘리므로 구조적으로 99.x%에 고정된다 — 정보량이 0이다. 실제로 변하는 양은 "이 도형을 적는 데 몇 항이 필요한가"이고, 이것은 마법진의 복잡도·등급과도 자연스럽게 연결된다.

### 4.2 푸터 — 승인된 "요약식 한 줄"의 문안

```
[좌] 복소 푸리에 · 중심 원점
[중] 6겹 회전 · 7획 · 43항으로 재현    Z(t) = ⋃ R^k z_j(t)
                (본문 크기)            (작게, 흐리게)
[우] [식 보기]   99%
```

- 문장이 앞, 구조식이 뒤. 구조식은 남기되 주인공 자리에서 내린다. `Z(t) = ⋃ R^k z_j(t)`는 정직하지만 **누가 무엇을 그려도 똑같이 나오는 템플릿**이라, 그것만 두면 지금의 (틀렸지만 변하는) 극좌표식보다 체감상 나쁘다.
- 획이 0개: `Z(t) = ∅ · 획을 그리면 식이 나타납니다`. 정확도는 `0%`가 아니라 `—`. 「식 보기」 disabled. "없음"과 "실패"는 구분되어야 한다.
- 혼합 대칭: `혼합 대칭 · 7획 · 43항으로 재현` + `Z(t) = ⋃_j S_j[z_j(t)]`.
- **그리는 중(비판 C-10)**: active 획은 분석에서 빠지므로 "7획"이 화면의 8획을 부정한다. 해결: active가 존재하는 동안 푸터의 수치 부분에 `opacity: .5`와 후행 `+1 대기`를 붙인다. 커밋 시 opacity가 돌아온다. 전환 애니메이션은 타이밍만 다루고 개수 불일치를 다루지 않으므로 불충분하다.

기존 `.copy-formula`(한 줄 복사)는 푸터에서 제거하고 모달로 이관한다 — 구조식 한 줄을 클립보드에 넣는 것은 가치가 거의 없다. 버튼 CSS는 `.open-formula`가 승계한다.

**주의**: `globals.css`의 `@media(max-width:480px){.stage-footer span:last-child{display:none}}`는 **위치 기반**이라 푸터 자식 순서를 바꾸면 엉뚱한 요소가 사라진다. 클래스 지정으로 바꾸고, 정확도는 모바일에서도 살린다. `code`에 overflow 규칙이 없어 식이 길어지면 버튼이 밀리는 문제도 함께 처리한다.

### 4.3 모달 「식 보기」

컨테이너는 기존 `.card-overlay`(fixed, 바깥 클릭 닫기)를 재사용하고 내부는 새 `.formula-sheet`를 만든다. **`.magic-card`는 재사용하지 않는다** — 350×500 고정에 `preserve-3d`/`rotateY` 플립 카드라 스크롤·details가 `backface-visibility`와 충돌한다. 금테(`1px solid #c9b16b` + 이중 링)만 승계해 "같은 세계의 물건"이라는 인상을 유지하고, 방사형 그라디언트를 뺀 평평한 스테이지 배경이 "수집품이 아니라 계측 결과"라는 위계를 만든다.

`.magic-card`와 `.formula-sheet`는 상호 배타로 연다(상태 분리: `cardOpen` / `formulaOpen`).

**위에서부터의 구성:**

```
1. 헤드 — FOURIER DECOMPOSITION / 마법진의 식
          43항으로 재현  ·  99% ✓     (항 수가 크게, 정확도는 배지)
          전체 98.2% · 최저 획 03 · 94.1%   ← 최저 획은 클릭 시 해당 카드로 스크롤

2. ★ 오버레이 (기본 켜짐, 시트 최상단)
   viewBox 0 0 100 100, 240~320px.
   원본 획 = 기존 그라디언트 / 재구성 곡선 = 대비색 반투명, 겹쳐 그림.
   대칭 복사본까지 전부 그린다(glow 필터 제거, strokeWidth 0.5 유지).

3. ★ 항 수 슬라이더  [1 ────●─── 43]
   기본값 = 자동 결정된 항 수. 움직이면 오버레이만 즉시 바뀐다.
   1항일 때 원이 이미 원인 것, 별이 몇 항부터 뾰족해지는지를 손으로 만진다.

4. 프레임/연산자 범례 (2줄, 상시)
   원점 = 캔버스 중심 (50,50) · y축 위쪽이 양수
   R_k z = e^(2πik/6) z   ·   M_x z = −z̄   ·   M_y z = z̄
   (해당 마법진이 실제로 쓴 연산자만)

5. 획 목록 (좌측 미니맵 sticky 240px / 우측 목록, ≤700px에서는 상단 스트립)
   ┌ 획 01   회전 ×6   6항   99.2% ✓
   │ z₁(t) = c₀ + Σ c_n e^(2πint)
   │ ▸ 계수 6개 보기                      ← details, 기본 접힘 · '고급'
   └
   호버/포커스/탭 시 미니맵에서 그 획의 모든 복사본만 불투명, 나머지 opacity .18

6. 외곽 실루엣 (참고)
   r(θ) = 29.6 + 3.2cos(12θ − 1.29) + …     ← 정확도 표기 없음

7. 액션 — [평문 | LaTeX] [복사]
```

**획별 고유 색상은 금지한다.** 캔버스의 모든 획은 `url(#arcana-gradient)` 하나로 그려지고 그 그라디언트는 속성(신성/어둠·4원소)을 의미한다. 획마다 무지개색을 부여하면 그 색 언어가 무너지고 원소 accent(`#ff4d3d` 불, `#9be86b` 바람)와 충돌한다. 획 식별은 번호 + 미니맵 하이라이트로 한다.

**상태 표현에 의미색(빨강/초록)을 쓰지 않는다.** 팔레트에 semantic 쌍이 없고 빨강·초록이 이미 원소 의미를 갖는다. 목표 달성은 accent 막대 풀 불투명 + `✓`, 미달은 막대 `opacity .45`. 불투명도만으로는 저시력 사용자에게 약하므로 기호와 숫자를 항상 병기한다.

**계수표는 `details` 기본 접힘 + '고급' 라벨.** 획이 1개일 때만 기본 펼침. 열은 `n | |c_n| | arg c_n | 막대`. `|c_n|` 내림차순 정렬하되 `n`을 반드시 같이 찍는다. `font-variant-numeric: tabular-nums` 필수. 극형식만 쓰고 직교형식 토글은 넣지 않는다(v1 컷).

**정정(비판 D-2)**: edge는 "재계산마다 항 순서가 뒤바뀐다"며 진폭 정렬을 반대했는데, 획은 커밋 후 불변이고 같은 입력의 부동소수점 연산은 비트 단위로 결정적이므로 이 위험은 실재하지 않는다. 실재하는 것은 "거의 같은 두 획이 다른 항 집합을 낸다"이며 훨씬 약한 문제다. 그리고 이것은 **선택과 표시의 혼동**이다 — 선택은 진폭 기준(최적성 정리), 표시는 사용자가 고르는 정렬(기본 진폭). 두 축은 독립이다.

### 4.4 문안 — 내부 예산 용어를 화면에서 없앤다

`항 상한 도달`, `목표 99% 미달`, `측정 한계 도달`, `항 예산 부족으로 일부 획 정밀도 하향` — 정직성 의도는 옳지만 사용자는 이 제약의 존재 이유도 모르고 바꿀 수단도 없다. 앱이 자기 사정으로 계속 사과하는 것으로 보인다.

```
사용자 언어:  이 획은 너무 복잡해서 여기까지 적었습니다  ·  96.4%
              (슬라이더를 최대로 밀면 차이가 오버레이에 그대로 보인다)
```

목표 미달을 99%로 반올림하거나 달성 배지를 다는 것은 금지한다. 표시 상한은 99.9%로 클램프해 근사식에 100%를 찍지 않되, 잔차가 정확히 0인 경우(직선 0항)만 100%를 허용한다.

**정확도 정의 각주는 삭제한다.** ui가 제안한 `정확도 = 1 − 평균 오차 ÷ 획 길이 · 화면에 그려진 곡선 기준`은 (a) 분모가 틀렸고(§1.6), (b) 사용자의 심리적 기준선(자기 손동작)과 시스템의 기준선(RDP·Catmull-Rom 이후 곡선)이 다르다는 것을 글자로 고백하는 문장이며, (c) 오버레이가 그 문장을 통째로 대체한다. 보여주면 설명할 필요가 없다.

### 4.5 카드 뒷면과 진입 경로

`.card-back`의 `<dt>극좌표식</dt>`을 `<dt>구조식</dt>` + `Z(t) = ⋃ R^k z_j(t)`로 바꾸고, `<dt>분해</dt><dd>7획 · 43항 · 99%</dd>`를 추가한다. 계수는 카드에 넣지 않는다 — 카드는 수집품이고 시트는 계측 결과다.

**「마법진 완성」 → 카드 뒷면 → 「전체 식 보기」 경로를 만든다.** 사용자가 자기 도형의 식을 가장 듣고 싶어 하는 순간은 그리는 도중이 아니라 완성 직후다. 「식 보기」를 푸터에만 두면 그 절정의 순간을 카드에 넘기고 식은 그리기를 방해하는 버튼으로 남는다. (두 오버레이는 상호 배타이므로 카드를 닫으며 시트를 연다.)

### 4.6 접근성

`role="dialog" aria-modal="true" aria-labelledby`, Escape 닫기, 오픈 시 닫기 버튼에 포커스, body 스크롤 잠금. 각 획 블록은 `tabIndex={0}`으로 `onFocus`가 hover와 같은 하이라이트를 준다 — 호버 전용 하이라이트는 키보드와 터치에서 그냥 사라지는 기능이 되므로 대체는 선택이 아니라 필수다. 터치에서는 탭 토글.

body 스크롤 잠금은 기존 `.card-overlay`에도 빠져 있다. 두 오버레이가 공유하는 훅으로 만들지 않으면 상태가 어긋나 스크롤이 영구 잠길 수 있다.

## 5. 성능

### 5.1 상한값 표

| 값 | 확정 | 근거 |
|---|---|---|
| 밀집 폴리라인 간격 | 0.25단위, `|D| ≤ 4096` | 선형보간 새그 0.008단위 |
| 표본 수 P | `clamp(round(2L), 128, 512)`, 짝수 | 간격 ≤ 0.5단위 |
| 후보 대역 K_max | `min(P/4, 64)` | 2배 오버샘플 여유 강제 |
| 유지 항 상한 T_max | **24** | 실측 최악 8항 → 3배 여유 |
| 전역 항 예산 | **없음** | 비판 C-1 |
| 오버레이 재구성 점수 Q | `clamp(8·max|n|, 64, 512)` | 최고 조화를 8점/주기로 |
| 획 수 상한 | 없음(계측만) | 100획 초과 시 재검토 |
| Web Worker | 없음 | 동기 작업 50ms 초과가 도입 기준선 |

### 5.2 캐시 — id와 WeakMap의 역할 분리

`Stroke`에 `id: string`을 추가하되 **React key와 memo 컴포넌트 전용**으로 쓴다. 스펙트럼 캐시는 모듈 스코프의 `WeakMap<Stroke, Spectrum>`이다. 둘 중 하나를 고르는 문제가 아니라 서로 다른 두 문제다.

- **WeakMap인 이유**: 획은 `endStroke`에서 한 번 만들어진 뒤 변형되지 않고, undo/redo는 동일한 객체 참조를 배열 사이에서 옮길 뿐이다. 객체 아이덴티티가 기하 아이덴티티와 정확히 일치한다. 축출 로직이 필요 없고, 지우개로 획이 사라지면 GC가 캐시도 회수한다. id를 캐시 키로 쓰면 마이그레이션 실수나 UUID 재생성으로 서로 다른 기하가 같은 키를 갖는 사고가 가능하고, 그때 증상은 "틀린 식이 표시됨"이라 발견이 늦다.
- **id인 이유**: 현재 렌더 키가 `${index}-${copy}`인데 지우개가 술어 필터로 중간 획을 지우면 뒤 획의 인덱스가 전부 밀린다. 지금은 path가 상태 없는 요소라 증상이 없지만, 모달에 획별 펼침 상태와 하이라이트가 생기면 즉시 엉뚱한 획으로 튄다.

**캐시 키의 완결성**: 대칭을 계수 변환으로 유도하므로 계수는 획 자신의 기하에만 의존한다 — `symmetry`/`rotationCount`는 키에 들어갈 필요가 없다. 목표 정확도는 2단(항 선택)에만 관여하므로 무효화 대상이 아니다. **이 완결성은 전역 예산을 폐기했기 때문에 성립한다**(비판 C-1).

### 5.3 useMemo 2단 분리

```
1단: useMemo(() => strokes.map(fitCached), [strokes])
2단: useMemo(() => analyze(spectra, target), [spectra, target])
모달 상세: formulaOpen을 의존성에 넣어 지연 계산
```

현행은 `[strokes]` 하나에 전부 매달려 있어 획 1개가 추가돼도 전체가 다시 돈다. 2단 분리 + WeakMap이면 커밋당 실비용이 획 1개 적합이다. 2단을 분리하는 실익은 항 수 슬라이더를 움직일 때 변환이 한 번도 다시 돌지 않는다는 점이다 — `truncate`만 재실행된다.

`displayStrokes`(렌더용, active 포함)와 `strokes`(분석용)를 타입 수준에서 분리해 메모 경계에 active가 딸려 들어가는 것을 막는다.

### 5.4 진짜 병목은 렌더 경로다

푸리에 최적화보다 **먼저** 획별 렌더 메모이제이션을 넣는다. 현행은 매 `pointermove`마다 `displayStrokes` 전체를 다시 map한다. 최악 상황 400개 path × 제어점 20개 × `toFixed` 6회 = 48,000회의 문자열 할당이고, perf 실측 3.66ms(M4) — 저사양 환산 약 18ms로 60Hz 예산도 넘긴다. 확정된 푸리에 전체 비용보다 4배 이상 비싸다.

`id` 기반 key + `StrokeLayer` memo면 그리는 중 갱신 대상이 active 획 1개로 줄어든다. active는 `simplify` 전이라 점이 계속 늘어나므로(360점 × 8사본 ≈ 1.3ms) 필요하면 active만 사본 렌더를 생략하거나 rAF로 묶는다.

이 작업을 이번 범위에 **포함한다.** id 부여가 캐시 설계와 맞물려 있고, 별도 커밋으로 떼면 id를 두 번 도입하게 된다.

### 5.5 Worker를 쓰지 않는 이유 — 논거 교체

**정정(비판 D-3)**: perf의 "structuredClone 0.24ms가 전체 0.89ms의 27%"라는 논거는 자기부정적이다. 비율이 나쁜 이유는 전체가 작기 때문이고, 워커가 정말 필요할 만큼 무거워지면 이 비율은 저절로 작아진다. 결론은 맞고 논거만 무효다.

남기는 기준은 절대값 하나다: **동기 작업이 지속적으로 50ms를 넘길 때만 워커를 도입한다.** 푸리에가 도는 시점은 `pointerup`이지 `pointermove`가 아니므로 실제 예산은 INP 200ms 쪽에 가깝다.

답이 바뀌는 조건을 명시해 둔다: P를 1024로 올리거나, T_max를 256으로 올리거나, 드래그 중 실시간 분석을 하거나, 획이 100개를 넘으면 재검토한다. 그 전에는 하지 않는다.

냉시작(localStorage 복원) 배치만 `requestIdleCallback`으로 미루되 `setTimeout` 폴백을 둔다. `page.tsx`에 죽어 있는 `idleTimer`(`setTimeout(() => undefined, 100)`)가 원래 이 용도로 의도된 흔적으로 보이므로 지우지 말고 여기에 용도를 준다.

디바운스는 불필요하다 — `endStroke`는 획당 1회 발생하는 이산 이벤트다.

| E19 | `simplify` 재귀 깊이 | 매우 긴 획에서 스택. 반복형으로 바꾸거나 입력 점 수 상한 | tolerance를 낮추려는 유혹과 함께 위험해짐 |
| E20 | 첫 저장이 로드를 덮어씀 | `restored.current` 가드 유지. 로더를 lib으로 옮기며 setStrokes 타이밍이 바뀌면 이 가정이 깨짐 | 로드가 부분 실패해 빈 배열을 넣으면 원본이 즉시 저장으로 날아감 |

**E11 + E12가 가장 위험한 조합이다.** 손상된 드래프트가 살균 없이 로드되어 NaN을 만들고, 저장 effect가 그 NaN 상태를 즉시 localStorage에 되써서 영구화한다. 살균과 로더 이전을 **같은 커밋**에서 처리한다.

**이번 범위에 섞지 않을 인접 결함**: `arcana-card-v1`이 쓰기 전용으로 방치된 것, `saved` 배지가 리셋되지 않는 것, `active.points.length > 2` 조건. 눈에 띄겠지만 별개 이슈다.

## 7. 테스트 전략

Vitest 하나를 도입한다(`npm i -D vitest`, 설정 파일 없음). 테스트는 `lib/*.test.ts`로 소스 옆에 둔다. **범위를 `lib/` 순수 함수로 엄격히 제한한다** — jsdom 없음, testing-library 없음, 컴포넌트 테스트 없음.

Vitest를 고른 이유는 설정 파일 0개로 TS를 실행하고 tsconfig의 `paths`를 읽어 테스트와 앱이 동일한 import 문을 쓰기 때문이다. `node --test --experimental-strip-types`는 의존성이 0이지만 플래그·확장자 명시·별칭 미해석이라는 마찰 세 개가 붙는다.

테스트가 값을 하는 지점은 아주 좁고 아주 뾰족하다. 호길이 재매개화와 열린 획 처리, 이 두 곳은 버그가 나면 "그럴듯하지만 틀린" 출력을 낸다 — 정확도는 99%라고 뜨는데 곡선은 다르다. 눈으로는 안정적으로 못 잡는다. 반대로 UI 테스트는 설정 비용이 크고 발견하는 버그가 적다.

## 8. 남은 위험과 미해결 질문

### 8.1 감수하는 위험

**R1. 열린 획 식이 승인된 형태와 다르다.** 승인된 `z(t) = Σ c_n e^{2πint}` 앞에 아핀 항 `z₀ + Δt`가 붙는다. 이는 사용자가 제시한 대안 중 하나이고, 닫힌 획은 승인된 형태 그대로이며, 모달에 `sin(πnt) = (e^{iπnt} − e^{−iπnt})/2i`를 병기해 같은 복소 푸리에임을 밝힌다. 대안(거울 확장)은 항 수가 3~14배이고 "t는 왕복"이라는 각주 부채가 있어 명백히 열등하다.

**R2. 정확도가 "표본에서의 오차"이지 "연속 곡선과의 오차"가 아니다.** 표본 간격이 0.5단위 이하로 촘촘해야 이 근사가 정당하다. T7이 이것을 감시한다.

**R3. 재구성 오버레이가 기본 켜짐이면 시트가 복잡해 보일 수 있다.** 대칭 복사본까지 다 그리면 회전 8 × 다획에서 path가 수십 개다. glow 필터를 빼고 `strokeWidth 0.5`를 유지하면 부담은 없다. 이 위험보다 오버레이가 만드는 신뢰가 훨씬 크다고 판단했다.

**R4. 렌더에서 닫힌 획을 실제로 닫으면 사용자가 남긴 미세한 틈이 사라진다.** 임계가 `g ≤ 0.03L`이므로 시각적 변화는 미미하지만, 그림 인상이 바뀐다는 지적은 유효하다. 되돌리기 쉬운 결정이므로 구현 후 눈으로 판단한다.

**R5. 시작점·방향에 따라 계수가 달라진다.** 정준화를 하지 않으므로 "같은 원을 3시에서 시작해 그리면 12시에서 시작한 것과 위상이 다르다"는 사실이 남는다. 이는 에피사이클 애니메이션을 사용자의 시작점에서 출발시키기 위해 의도적으로 감수하는 대가다(D12). **대신 "같은 모양이면 같은 식"이라는 문구를 UI와 문서 어디에도 쓰지 않는다.**

### 8.2 결정된 질문 (2026-08-13 승인)

**Q1. 항 수를 위력/복잡도 공식에 연결할 것인가. → v1은 표시만.**
비판 2는 "식이 게임에 아무 영향을 주지 않는 부속물"이라고 지적했고, 항 수는 정확도가 고정된 이상 실제로 변하는 유일한 수치다. 다만 편입은 등급 컷(60/150/260) 재조정을 부르는 밸런스 변경이다. **v1에서는 analysis 패널에 표시만 하고 `power` 공식은 손대지 않는다.** 기존 마법진의 등급이 이번 변경으로 움직이지 않는다. 위력 편입은 데이터를 모은 뒤 별도 승인으로 v2에서 판단한다.

**Q2. 항 수 슬라이더가 "자동 증가" 방향과 충돌하는가. → 충돌하지 않는다.**
슬라이더는 **자동 결정된 항 수를 기본값으로 두고, 그 이하로 미리보기만 바꾸며, 저장 상태를 변경하지 않는다.** 자동 결정이 주(主)이고 슬라이더는 그 결정을 눈으로 확인하는 장치다. 사용자가 슬라이더 값을 "확정"하는 기능은 v1 범위 밖이다.

**Q3. 정준화를 뺄 것인가. → 영구 미채택.**
에피사이클 재생 애니메이션을 나중에 넣을 계획이 확인되었다. 정준화하면 t=0이 표준 위치로 옮겨져 **애니메이션이 사용자가 그리기 시작한 곳이 아닌 지점에서 출발한다.** 미채택을 지금 확정해 두면 v2에서 애니메이션을 붙여도 계수가 바뀌지 않는다. `Spectrum`은 이미 애니메이션에 필요한 정보를 모두 담고 있다(`terms[{n, re, im}]`, 열린 획은 `z₀`·`Δ`).

**Q4. 계수표를 뺄 것인가 접을 것인가. → 접어서 남긴다.**
진위 증거로서 존재 자체에 의미가 있다. 기본 접힘 + '고급' 라벨.

**Q5. Vitest 도입. → 도입한다.**
`npm i -D vitest`. 설정 파일 없이 TS를 실행하고 tsconfig의 `paths`를 읽어 테스트와 앱이 동일한 import 문을 쓴다. 범위는 `lib/` 순수 함수로 엄격히 제한한다(§7).

**Q6. `arcana-card-v1` 정리. → `version` 필드만 지금 넣는다.**
`saveCard`가 `metrics`를 통째로 직렬화하는데 읽는 코드가 프로젝트 어디에도 없다. `metrics` shape이 바뀌므로 이번에 닿기는 하지만 본 작업의 범위는 아니다. 나중에 갤러리를 붙일 때 형식 없는 과거 데이터가 남지 않도록 `version` 필드만 추가하고, `saved` 배지 리셋 문제는 별도 이슈로 남긴다.

### 8.3 구현 후 실측할 항목

아래는 미결 설계 사항이 아니라, 구현이 끝난 뒤 실제 손그림으로 확인해 조정할 값들이다.


- **T_max=24와 K_max=64가 실제 손그림에서 얼마나 걸리는가.** 합성 픽스처 최악이 8항이므로 여유가 크지만, 실제 손떨림 낙서로 확인이 필요하다. 상한 도달 칩이 자주 뜨면 그건 정직성 문제가 아니라 상한이 낮다는 신호다.
- **획 50개 · 제어점 20개가 정말 상한인가.** 현재 캔버스에는 획 개수 제한이 없고 **v1에서도 걸지 않는다.** 실사용에서 획이 2~4배로 늘어 동기 작업이 50ms를 넘기 시작하면 그때 Web Worker 판단(D15)을 재검토한다. 그 전까지는 상한을 두지 않는 편이 사용자 자유도에 유리하다.
- **닫힘 임계 0.03의 현장 적합성.** 실제 사용자가 그리는 원의 끝점 간격 분포를 몇 개만 재보면 확정할 수 있다.
